# Мобильный клиент v0.2.0: реализация и проверка

Рабочая ветка: `v0.2.0-dev`. Это автономный Flutter-клиент в `orange_notes_mobile/`, отдельный от PySide6 desktop-приложения. Офлайн-работа не требует запущенного компьютера. Статус конкретных экранов, транспорта и автоматических тестов сверяется с кодом и отчётом текущего запуска; подготовленная CI-конфигурация сама по себе не подтверждает успешную нативную сборку.

## Структура

- `lib/` — Dart-модель, локальный репозиторий, CRDT, сервисы и Flutter-экраны.
- `test/` — проверки CRDT, SQLite и интерфейса.
- `test/fixtures/protocol_v1.json` — общие векторы совместимости с desktop.
- `android/`, `ios/` — нативные оболочки и разрешения платформ.
- `.github/workflows/mobile-ci.yml` — форматирование, анализ, тесты, Android APK и неподписанная iOS IPA.
- `.github/workflows/mobile-ios-delivery.yml` — отдельная ручная подписанная доставка при наличии материалов владельца.

## Контракт CRDT

Desktop остаётся источником проверочных векторов: `python tools/mobile_protocol_fixtures.py --check` воспроизводит ожидаемые результаты прямо через `app.services.p2p_sync.Replica` и сравнивает их с сохранённым JSON. Dart-тесты применяют те же строки дельт и сравнивают принятие, итоговые поля и историю конфликтов. Генератор без `--check` применяется только при намеренном изменении контракта с ревью diff.

Десять сценариев включают кириллицу, emoji и HTML без преобразования, одинаковые часы разных авторов в обоих порядках доставки, независимость удаления от изменения тела, явное восстановление, повторную доставку, подмену содержимого при одинаковом actor/clock, неизвестное поле, чужое пространство и повтор JSON-ключа. Этот набор подтверждает совместимость покрытых сценариев; он не заменяет испытания сетевого обмена и все ограничения безопасности.

SQLite используется через транзакционный репозиторий. Целочисленный локальный ID и UUID сущности имеют разные назначения. `note_links` — производный локальный индекс; его целочисленные ключи не пересылаются как глобальные идентификаторы. Сохранение локальной правки и запись outbox должны происходить в одной транзакции. ACK после durable commit не означает автоматическое разрешение пользовательского конфликта.

Текущая SQLite-схема мобильного клиента — самостоятельная схема с совместимыми UUID и журналами протокола, а не побайтовый клон desktop-БД. Копирование desktop-файла БД вместо протокольного обмена не поддерживается. Один мобильный файл БД соответствует одному пространству. Теги пока локальные: протокол v1 передаёт только `title`, `body`, `lifecycle`; синхронизация тегов, папок, напоминаний и нескольких пространств требует отдельного расширения протокола.

## Реальный сетевой адаптер

`lib/services/p2p_transport.dart` использует `dart:io` SecureSocket и минимальную версию TLS 1.3. Доверенная цепочка и имя сервера проверяются библиотекой, затем до отправки данных сверяется полный SHA256 сертификата. Сервер требует сертификат клиента и сверяет сертификат, actor и workspace. Кадр совместим с desktop: 4-байтовая длина big-endian и JSON, не более 528384 байт; исходная строка дельты сохраняется для SHA256. ACK выдаётся после завершения async commit callback; ошибка, дедлайн или отзыв доверия исключают ACK. Таймаут ограничивает обмен, но не отменяет уже начатую транзакцию SQLite: повтор безопасен благодаря inbox.

Локально пройдены 8 тестов реальных TLS-сокетов Dart: успешный обмен и повтор, неверный отпечаток, недоверенный клиент с валидной CA, неверное имя сервера, ошибка commit, дедлайн, отзыв перед ACK и отказ небезопасной конфигурации. Для этих тестов используются явно публичные тестовые ключи в `PUBLIC_TEST_TLS.json`; применять их для сопряжения запрещено. Это не проверка Android/iOS-стека на физическом устройстве. На iOS локальная identity передаётся PKCS12, доверенная CA — DER; адаптер принимает PKCS12 и преобразует PEM CA в DER. Секретный ключ не размещается в QR.

## Проверки

Локальные команды из корня мобильного проекта:

```text
flutter pub get
dart format --output=none --set-exit-if-changed lib test
flutter analyze --fatal-infos
flutter test --coverage
flutter build apk --debug
flutter build ios --release --no-codesign
```

Последняя команда требует macOS/Xcode. Android APK из CI — debug, не подписанный релиз для магазина. Подробности unsigned IPA, повторной подписи и TestFlight: [IOS_DELIVERY.md](IOS_DELIVERY.md).

Обязательная отдельная ручная приёмка: холодный запуск и перезапуск без сети; отказ в доступе к камере и микрофону; сохранение при закрытии экрана; поиск и wiki-ссылки на кириллице; дубли заголовков; масштаб текста; жесты графа; отзыв доверия; обрыв и восстановление LAN; Android–desktop и iPhone–desktop через реальные сети. Системное STT может зависеть от настроек и сервисов ОС: оно не объявляется гарантированно локальным распознаванием.

До выполнения этих проверок не заявляются физическая совместимость устройств, работа в фоне iOS и готовность к магазинам приложений. Базовая архитектурная спецификация: [MOBILE_CLIENT_SPEC.md](MOBILE_CLIENT_SPEC.md); сетевой desktop-контракт: [P2P_NETWORK_PHASE2.md](P2P_NETWORK_PHASE2.md).

## Контроллер подключения

`MobileSync` хранит identity и доверенные устройства в системном защищённом
хранилище (`flutter_secure_storage`); QR не содержит приватного ключа.
Файл identity JSON импортируется отдельно и содержит `actor_id`, `ca_pem`,
`certificate_pem`, `private_key_pem`; на iOS вместо PEM identity используется
`pkcs12_base64` и при необходимости `password`. Actor должен совпадать с
идентификатором устройства, показанным на экране синхронизации. Выдача сертификатов
общей доверенной CA пока выполняется вне приложения.

QR JSON содержит `actor_id`, `workspace_id`, `host` (локальный IP), `port`,
`server_hostname`, `fingerprint_sha256` (64 lowercase hex), необязательное `name`.
Пространство можно присоединить только на пустой локальной БД; существующие
заметки не перемещаются в чужое пространство при сканировании QR.
Сеть не запускается при старте приложения. После явного обмена отображается порт
приёма: его нужно передать настройке desktop peer. Это foreground-прототип,
без автоматического мобильного mDNS/двустороннего мастера выдачи сертификатов.
Статус подтверждает отдельно исходящие операции, а не выдумывает завершение
двусторонней синхронизации.
