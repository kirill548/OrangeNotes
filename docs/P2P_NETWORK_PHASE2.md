# P2P: сетевой прототип фазы 2

Дата: 14 октября 2026. Ветка: `v0.2.0-dev`. Это экспериментальный фундамент,
а не готовая синхронизация в интерфейсе опубликованной v0.1.5.

## Что реализовано

| Компонент | Реализация | Граница ответственности |
|---|---|---|
| Обнаружение | `app/services/p2p_discovery.py`, `MdnsDiscovery` | Фоновый Zeroconf/mDNS; объявления не предоставляют доверие |
| Канал | `app/services/p2p_transport.py` | Асинхронный TCP, только TLS 1.3, взаимная проверка сертификатов и SHA256-отпечатков |
| Сопряжение | `pair_peer_qr` | Полный отпечаток сертификата и явное подтверждение; без PIN/PAKE |
| Фоновый узел | `app/services/p2p_node.py`, `P2PNode` | Поток владельца SQLite, asyncio и TLS, операции через Future |
| Хранилище | `app/database/p2p_store.py`, `P2PStore` | Отдельная подготовленная UUID-копия SQLite, одно явно выбранное пространство |
| Слияние | `app/services/p2p_sync.py` | LWW-регистры заголовка/текста, независимое состояние удаления, повторяемый журнал |

Ни конструкторы сервисов, ни обычный запуск приложения не включают сетевое
обнаружение или синхронизацию автоматически. Обычные изменения через GUI `Store`
ещё не маршрутизируются в Outbox: синхронизируемые изменения должны проходить
через `P2PStore.mutate_note`. Исходная пользовательская база не мигрирует.

## Обнаружение без раскрытия содержимого

`MdnsDiscovery.start()` запускает собственный поток и публикует
`_orangenotes._tcp.local.`. Имя экземпляра и TXT содержат временный UUID сеанса;
остальные TXT-поля — версия и недоверенная подсказка `pairable`/`paired`.
Постоянные UUID устройств и пространств, заголовки и текст заметок не публикуются.

`trusted_scopes(candidate)` обращается к локальному реестру разрешений.
`candidates(workspace_id=..., paired_only=True)` фильтрует представление результатов
по этому реестру. Это не аутентификация: поддельное объявление или совпадение адреса
не заменяет последующую проверку сертификата и доступа на транспорте.

Ограничения: до 64 записей и 64 ожидающих событий, TTL записей 30 секунд,
TXT до 512 байт, разрешение одной записи до 250 мс. `stop()` отменяет браузер,
снимает объявление, закрывает Zeroconf и ожидает завершения потока. Ошибка запуска
доступна вызывающему коду; отсутствие необязательной зависимости не ломает GUI.

## TLS и явное доверие

Используются стандартные `asyncio` и `ssl`; обе границы версии закреплены на TLS 1.3,
проверка сертификата обязательна. Клиент дополнительно проверяет имя сервера.
Сервер и клиент сопоставляют полный SHA256-отпечаток сертификата с разрешённой
парой actor/workspace UUID. UUID из JSON сам по себе не даёт доступа.

Для прототипа сертификаты, приватные ключи и доверенный CA предоставляются заранее.
`pair_peer_qr` принимает сертификат, полный отпечаток из доверенного внеполосного
канала и `confirmed=True`. Это API подтверждения, без экрана QR-сканера,
автоматической выдачи сертификатов, PIN-аутентификации или PAKE. Приватные ключи
пока не интегрированы с защищёнными хранилищами ОС.

Кадр — 4-байтовая длина и JSON UTF-8 с версией, actor/workspace и одной дельтой.
Размер ограничен до чтения тела; повторные JSON-ключи, неправильные идентичности,
неизвестные поля конверта и повреждённые данные отклоняются. Контроль целостности
и аутентичность канала обеспечивает TLS; отдельный самодельный MAC не вводится.
Отправитель получает ACK с SHA256 дельты только после успешного завершения
транзакционного обработчика получателя. По умолчанию дедлайн 5 секунд, максимум
30 секунд; число активных прикладных соединений ограничено.

## SQLite и восстановление после обрыва

Перед открытием проверяются подготовленные UUID-сопоставления и привязка устройства.
Один экземпляр `P2PStore` обслуживает одно пространство и принадлежит одному потоку.
SQLite работает с FK, WAL и `synchronous=FULL`.

```text
локальное изменение:
BEGIN IMMEDIATE -> CRDT + notes + sync_events + sync_outbox -> COMMIT

приём:
проверка actor/workspace -> BEGIN IMMEDIATE -> проверка dot/digest
-> CRDT + notes + sync_events + sync_inbox -> COMMIT -> ACK

отправитель:
проверенный ACK -> sync_outbox_ack(sha256, peer_actor)
```

`sync_events` сохраняет принятую историю для восстановления победителей LWW и
конфликтов. `sync_inbox` дедуплицирует SHA256 и dot `(actor_id, clock)`;
противоречащая повторная операция отклоняется. ACK учитывается отдельно для
каждого peer и не удаляет историю. Обрыв после commit до ACK приводит к повторной
доставке той же операции, а не к повторному созданию заметки.

Передаются только `title`, `body`, `lifecycle`. Таблица `note_links` остаётся
производным локальным индексом. Папки, метки, расписания, вложения, настройки ИИ,
разрешения и сами сущности пространств пока не синхронизируются. Полноценная
компактация, снимки и пересылка операций третьих устройств ещё не реализованы.

## Проверки и пределы подтверждения

- `tests/test_p2p_mdns.py`: жизненный цикл, ограничения, локальные фильтры,
  отклонение недоверенных TXT; отдельный реальный тест двух Zeroconf-узлов.
- `tests/test_p2p_discovery.py`: совместимость прежнего UDP-эксперимента.
- `tests/test_p2p_network.py`: обмен через локальные TLS-сокеты,
  сертификаты, повторы, обрывы и транзакционная доставка.
- Базовые CRDT/UUID-проверки остаются в `tests/test_p2p_sync.py` и
  `tests/test_p2p_identity.py`.

На Windows проверено взаимное обнаружение двух реальных Zeroconf-экземпляров
через multicast loopback. Для запуска этого теста задаётся
`ORANGE_NOTES_TEST_MDNS=1`; без явного включения он пропускается.
Это не подтверждение работы на двух физических устройствах LAN/Wi-Fi.
Итоговые результаты полного CI фиксируются отдельно после завершения прогонов.
Flutter-приложение, фоновые ограничения Android/iOS, отзыв доступа на физических
устройствах и длительные сетевые испытания пока не квалифицированы.

См. [общую архитектуру](P2P_SYNC_ARCHITECTURE.md),
[мобильную спецификацию](MOBILE_CLIENT_SPEC.md) и [план развития](../ROADMAP.md).

## Фоновый узел

`app/services/p2p_node.py` объединяет SQLite и asyncio/TLS в отдельном потоке.
`start()` / `wait_ready()` запускают явно подключённую реплику; `mutate_note()`,
`get_note()`, `pending_outbox()` и `sync_to()` возвращают `Future`.
`stop()` отменяет сетевые операции, закрывает сервер и БД в потоке владельца.
Неподтверждённые операции остаются в Outbox после остановки.

Один цикл отправляет по умолчанию 32 дельты, максимум 128, с бюджетом 30 секунд.
Ограничение соединений относится к установленным прикладным сессиям;
отдельного лимитера TCP/TLS-handshake до аутентификации пока нет.
Синхронный SQLite и системный файловый ввод-вывод не получают принудительного
прерывания от таймера asyncio; после истечения срока ACK отправлять нельзя.
Это ограничение не затрагивает поток GUI, поскольку БД принадлежит фоновому узлу.

Совместимость копий и экспорта проверяет `tests/test_p2p_export.py`,
транзакции — `tests/test_p2p_store.py`, два фоновых узла — `tests/test_p2p_node.py`.

## Схема журнала

| Таблица | Ключ | Содержание |
|---|---|---|
| `sync_p2p_schema` | `singleton=1` | Версия и привязка actor/workspace к локальному пространству |
| `sync_events` | `(actor_id, clock)` | Канонические дельты для восстановления LWW |
| `sync_outbox` | `sha256` | Неизменяемые исходящие дельты |
| `sync_outbox_ack` | `(sha256, peer_actor)` | Отдельное подтверждение каждого получателя; FK к Outbox |
| `sync_inbox` | `sha256`, UNIQUE `(actor_id, clock)` | Принятые операции и защита от повторов |

Остальные таблицы сохраняют локальные INTEGER PK/FK; сетевые идентификаторы — UUIDv4.
Готовая копия с метаданными не открывается старым валидатором восстановления напрямую:
`export_legacy_copy` создаёт отдельную совместимую копию без журналов синхронизации.
Исходник и его WAL не изменяются.
