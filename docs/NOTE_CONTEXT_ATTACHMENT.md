# Динамический контекст заметок

В окне помощника панель «Привязанные заметки» позволяет явно выбрать записи для следующего вопроса. Поиск в панели выполняется по заголовкам; запись без заголовка отображается как «Без названия». Можно добавить до восьми заметок и удалить отдельную привязку. Новый разговор очищает привязки.

## Область доступа

Выбор ограничен текущим личным или рабочим пространством. Переключение пространства очищает привязки. Архив и корзина доступны только при включении соответствующих фильтров; отключение фильтра удаляет недоступные привязки. При отправке логика приложения повторно проверяет идентификаторы и область доступа: устаревший список интерфейса не даёт доступа к перемещённой или удалённой записи.

На время запроса выбор контекста и фильтры блокируются. Фоновый запрос получает отдельный снимок идентификаторов. Изменение или перемещение заметки во время ответа отменяет публикацию устаревших фактов. История другого пространства исключается из запроса.

## Что получает модель

Привязки имеют приоритет перед автоматически найденными источниками. Одна запись не добавляется дважды. Текст заметки передаётся как данные в JSON-пакете пользовательского сообщения, а не добавляется к системным инструкциям. Каждый источник содержит номер источника, ID заметки, ревизию, тип `attachment`, текст и смещение фрагмента.

**Прикрепление не означает передачу заметки целиком.** Для каждой привязки выбирается релевантный вопросу фрагмент длиной до 500 символов. Для длинных заметок поиск фрагмента проходит по всей записи; фрагмент может находиться после первых 100 000 символов. Если вопрос не выделяет конкретный фрагмент, используется ограниченное превью. Для разбора другой части записи уточните вопрос.

Бюджет запроса остаётся ограниченным. Автоматически найденные источники удаляются раньше привязок. Если обязательный прикреплённый контекст не помещается, запрос сообщает об ошибке вместо незаметного удаления привязки. Отсутствие модели сохраняет режим поиска: пользователь получает разрешённые источники без выдуманного ответа.

## Проверка ответа

Системный промпт и требования grounding не ослабляются. Факты требуют действительных номеров источников, дословных цитат и актуальных ревизий. Потоковые сегменты проходят существующий `StreamSegmentValidator` до отображения. Команды внутри заметки не становятся разрешениями на действия или доступ к другому пространству. Отмена запроса сохраняет существующие правила очистки невалидированного буфера.

## Проверка реализации

Новые проверки находятся в `tests/test_note_context.py`, `tests/test_note_context_security.py`, `tests/test_note_context_ui.py` и `tests/test_note_context_integration.py`. Они используют синтетические заметки и контролируемые ответы, без скачивания модели и сетевых запросов. Это проверка сборки контекста, изоляции и интерфейса, а не подтверждение качества конкретной языковой модели.

Фактические результаты регрессии и проверки сборки фиксируются отдельно в `work/note-context/report.json` и `work/note-context/report.md`. Локальный прогон не подтверждает запуск на Linux/macOS и не означает обновление опубликованных дистрибутивов.
