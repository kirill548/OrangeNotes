# v0.1.3: локальный движок и Complete Edition

Дата анализа: 10 октября 2026. Это проектное решение и первичный эксперимент,
а не обещание одинаковой скорости на всех компьютерах.

## Решение

Для первой Complete Edition использовать предварительно упакованный **изолированный
Ollama runtime** и проверенное хранилище моделей. С точки зрения пользователя
модель встроена и готова без установки Ollama; технически инференс остаётся отдельным
принадлежащим приложению процессом. Lite продолжает поддерживать внешний Ollama,
существующие AI-packs и режим поиска без модели. Настройки пользователя имеют приоритет
перед bundled defaults, поэтому обновление не переключает ранее выбранную модель.

Прямой GGUF через llama.cpp остаётся возможным следующим backend. Подключать его
лучше отдельным worker/server, а не загружать native inference в GUI-процесс.

## Движки

| Критерий | llama-cpp-python in-process | Изолированный llama-server | Ollama external / bundled |
|---|---|---|---|
| Модель | GGUF, явный путь | GGUF, явный путь | собственные manifests/blobs, импорт GGUF |
| Существующий клиент приложения | нужен новый адаптер | нужен OpenAI/SSE адаптер | совместим с текущим NDJSON |
| Ошибка native runtime/OOM | может завершить GUI-процесс | изолирована процессом | изолирована процессом |
| Отмена | cooperative/native callback | закрытие HTTP + server cancellation | текущий QNetworkReply.abort |
| Упаковка | разные wheels/build flags для backend | platform-specific runtime/libs | platform-specific runtime/libs |
| Владение файлами | требуется отдельный sandbox | требуется отдельный sandbox | уже есть ManagedPackRuntime/AIPackStorage |
| Cold start и TTFT | требуется измерение | требуется измерение | требуется измерение |

Официальные [Python bindings](https://github.com/abetlen/llama-cpp-python)
предусматривают CPU и аппаратные варианты сборки. [llama.cpp](https://github.com/ggml-org/llama.cpp)
предлагает отдельный сервер и инструмент llama-bench. Вывод об изоляции GUI следует
из архитектуры процессов, а не из измерения скорости этих движков на данном хосте.

## Кандидаты Qwen

Размеры ниже — округлённые **десятичные** размеры GGUF из официальных файлов Qwen,
не размер финального установщика и не измерение RAM. Зафиксировать revision/hash
конкретного файла требуется на этапе подготовки модели.

| Кандидат | Q4_K_M | Q5_K_M | Роль в Orange Notes |
|---|---:|---:|---|
| Qwen2.5-1.5B-Instruct | 1.12 GB | 1.29 GB | основной компактный кандидат для общего диалога |
| Qwen2.5-Coder-1.5B-Instruct | 1.12 GB | 1.29 GB | необязательная модель для кода |
| Qwen2.5-3B-Instruct | 2.10 GB | 2.44 GB | кандидат повышенного качества, требует отдельного измерения |

Источники: [1.5B general](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/tree/main),
[1.5B Coder](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF/tree/main),
[3B general](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF/tree/main).
General [model card](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct)
описывает мультиязычность, включая русский; [Coder card](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct)
описывает специализацию на коде. Поэтому general Instruct — предварительный выбор
для заметок. Это продуктовая гипотеза, не доказанное превосходство в нашем RAG.

Q4_K_M выбран как исходный компактный кандидат. Q5_K_M нужно сравнить на одинаковых
prompt/context/seed/num_predict и железе; большее число бит само по себе не доказывает
улучшение extraction/grounding. Существующий Qwen3:4B сохраняется и может быть первым
Complete pack при наличии проверенных локальных assets и лицензий.

RAM = веса + KV-cache + runtime buffers + GUI/SQLite + запас ОС. VRAM зависит от
offload/backend/context, поэтому минимальные RAM/VRAM нельзя честно вывести только
из размера GGUF. Указанные в менеджере моделей оценки памяти остаются advisory.

## Первичный эксперимент и воспроизводимость

`tools/benchmark_local_engines.py` не загружает модели, не запускает пользовательский
Ollama и не показывает сырые токены. Выполняет три фиксированных задания: извлечение
телефона, синоним машина/автомобиль, отказ при отсутствии пароля. Измеряет wall-clock
TTFT первого content token и полную latency; показывает медиану/p95 завершённых
запросов. Errors и пропуски не превращаются в нулевую задержку. Первый проход cold/
warm смешивать при сравнении нельзя: iteration 0 анализируется отдельно.

Пример для уже установленного локального сервера:

```sh
python -m tools.benchmark_local_engines --model qwen3:4b --repeats 5 --output work/engine-benchmark.json
```

Результаты текущего isolated run находятся в `work/v013-engine/results.json`;
сервер на 127.0.0.1:11573 запускается только для эксперимента и затем завершается
по собственному PID. Существующие веса не скачиваются и не удаляются. Аппаратный
placement проверяется через `/api/ps`, а не по наличию GPU на компьютере.

Фактический первый прогон Windows 11 с существующим **Qwen3:4B Q4_K_M**:

| Проверка | Результат |
|---|---|
| Извлечение телефона | timeout 30.031 s; TTFT неизвестен |
| Синоним машина/автомобиль | timeout 30.016 s; TTFT неизвестен |
| Канонический отказ (пароль отсутствует) | PASS; TTFT 7.953 s; полный ответ 9.547 s |
| Median завершённых запросов | 9.547 s, **только один sample**, не стабильный benchmark |
| Размер установленной модели | 2,497,280,371 bytes (API tags) |
| Resident model size / size_vram | 2,874,062,929 / 2,874,062,929 bytes (API ps snapshot) |

API ps указывает accelerator residency; тип GPU здесь не измерен. Это snapshot
модели, **не peak VRAM процесса**. Два таймаута и малая выборка не позволяют называть
Qwen3:4B идеальным Out-of-the-Box default для этого устройства. Нужны повторные
cold/warm испытания и компактный кандидат. Qwen2.5 general/Coder отсутствуют и
отмечены skipped; прямой llama.cpp не запускался. Таймауты не скрыты из общего
списка, но не участвуют в медиане успешно завершённых запросов.

Этот небольшой extraction benchmark **не заменяет** `test_ai_assistant_quality.py`,
проверку StreamSegmentValidator, дословных quotes, ревизий, prompt injection,
workspace boundaries и канонических отказов. Проверка одной подстроки не является
метрикой semantic precision/recall. Для сравнения квантов нужно запустить полный
Quality Suite отдельно на каждом установленном кандидате и записать model digest.

Ollama предоставляет server durations/token counts в
[API](https://docs.ollama.com/api/generate); они отличаются от wall-clock TTFT клиента.
Peak RAM/VRAM здесь не измеряется и остаётся `null`, а не заменяется размером весов.

## Контракт Complete pack

Поставка должна содержать engine/version, target platform + canonical architecture,
chat model, необязательную embedding model, лицензии/происхождение, SHA256 и размеры
всех model/runtime файлов. Только локальные relative paths; исключить symlinks,
traversal и незаявленные исполняемые файлы. Manifest сам по себе не цифровая подпись:
доверие начинается с проверенного установщика и release checksums.

Неизменяемые bundled assets отделены от writable managed `ai_packs/models`.
Runtime создаёт профиль/логи/служебные файлы только в пользовательском managed root.
Private endpoint не занимает внешний 11434; нельзя останавливать чужой daemon.
После подключения используется тот же OllamaClient, JSON-schema, fit_messages,
GroundingValidator, StreamSegmentValidator и механизм отмены.

Отсутствие embedding модели допускает FTS5/лексическое ранжирование, но интерфейс
не должен утверждать, что semantic embeddings работают. Complete без chat weights,
runtime или с неверными hashes должна отказываться собираться, а не называться готовой.

## Критерий выбора финального default

1. Проверенные license/source/revision и hashes конкретных весов/runtime.
2. Все safety/grounding tests проходят на каждой целевой платформе.
3. По крайней мере 20 cold и 20 warm запросов на CPU и доступных GPU, с hardware и
   backend version; cancellation/30-second deadline проверяются отдельно.
4. Отдельно измеренные peak RSS и accelerator memory; неизвестные метрики N/A.
5. Если бюджет времени/памяти превышен — понятный поиск, сохранённые заметки и настройки.

## Аппаратная квалификация Qwen2.5-1.5B Q4_K_M — 10 октября 2026

Официальный GGUF Qwen2.5-1.5B-Instruct проверен по SHA-256
`6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`
и импортирован в изолированный Ollama 0.35.1. Размер весов — 1,117,320,736 байт.
Тестовый хост: Windows 11, Ryzen 9 7845HX, около 32 ГБ RAM,
RTX 4060 Laptop GPU с 8188 МиБ VRAM.

| Серия | Запросы | Завершены | Таймауты | TTFT p50 / p95 | Latency p50 / p95 |
|---|---:|---:|---:|---|---|
| Cold, выгрузка модели перед каждым запросом | 60 | 0 | 60 | Нет измерения | Нет завершённых ответов |
| Warm | 60 | 59 | 1 | 78 / 94 мс | 141 / 172 мс |

Перцентили рассчитаны по завершённым запросам; таймауты остаются в общем
знаменателе. Cold не включает очистку файлового кэша ОС. TTFT означает первый
сырой content token транспорта, а не первый прошедший grounding текст в UI.
Первый warm-запрос превысил дедлайн, второй занял 15,437 секунды; эти результаты
не исключены. В исходном prewarm не был явно задан num_ctx; инструмент исправлен
для следующих запусков, но эта правка не приписывается уже снятым измерениям.

Пик RSS дерева процессов в cold-интервалах — 1,041,375,232 байта;
private commit — 2,653,310,976 байт. Это разные метрики и выборочные пики.
`/api/ps` подтвердил model residency 1,105,419,304 байта в VRAM;
это не измерение абсолютного пика VRAM процесса.

Фиксированный extraction benchmark: 19/60 проверок содержания в warm-серии.
Реальный Quality Gate кандидата: **2/16 PASS, 14 FAIL**, строгие канонические
отказы **0/10**, полный pipeline **2/6**. Синтетические проверки приложения
отдельно дали 59 PASS, 1 SKIP и 79 успешных подслучаев; они не доказывают качество
модели. Резервный поиск после ошибки генерации не считается успешным ответом LLM.

**Вердикт: текущая конфигурация модели/runtime не готова стать официальным
Complete default.** Необходимо проверить шаблон диалога и холодную инициализацию,
затем повторить квалификацию без ослабления guardrails. Исходные неуспешные серии
сохранены в `work/v013-engine/benchmark_report.json` и связанных артефактах.
Вывод не доказывает непригодность этих весов во всех альтернативных runtime.

CPU-only, Q5_K_M, 3B, прямой llama.cpp и аппаратные прогоны на Linux/macOS
в этом этапе **не измерялись**. Сравнение этих вариантов остаётся открытым.
