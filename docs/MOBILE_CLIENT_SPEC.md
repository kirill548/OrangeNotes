# Orange Notes: спецификация мобильного клиента

Статус: проектирование v0.2.0, 14 октября 2026 года. Это спецификация Flutter/Dart-клиента, а не готовое приложение iOS/Android. Мобильный проект, разрешения, нативные сборки и обмен между физическими устройствами ещё требуют реализации и проверки. Прототипы SQLite/CRDT в desktop-репозитории не подтверждают готовность мобильной синхронизации.

## 1. Границы первой версии

Основной сценарий: создать заметку без сети, отредактировать её и явно синхронизировать с доверенным компьютером в локальной сети. Учётная запись и центральный сервер не требуются. Отключённая синхронизация не мешает чтению и редактированию.

На телефон не устанавливаются автоматически Ollama, Whisper, веса моделей или desktop-бинарники. Голосовой ввод и ИИ — отдельные будущие возможности с явным согласием; интерфейс не обещает их наличие. P2P не открывает удалённый API ИИ компьютера.

## 2. Навигация и экраны

| Экран | Основные элементы | Поведение |
| --- | --- | --- |
| Заметки | Выбор пространства, поиск, список, кнопка «Новая заметка» | Сначала локальные данные; архив и корзина доступны отдельно |
| Быстрая заметка | Заголовок, текст, «Готово» | Сохранение в текущем пространстве без ожидания сети; состояние «Сохранено на устройстве» |
| Редактор | Заголовок, текст, вставка ссылки, меню действий | Автосохранение, восстановление черновика после перезапуска, ссылка открывает конкретную заметку |
| Связи заметки | Исходящие ссылки, обратные ссылки, неупомянутые связи | По умолчанию свёрнутая панель; не смешивает пространства |
| Граф знаний | Локальное окружение активной заметки, масштаб, возврат к центру | Нажатие на узел открывает заметку; сначала ограниченный подграф, а не тысячи узлов |
| Устройства и синхронизация | «Подключить устройство», «Синхронизировать», список доверенных устройств | Понятный результат последнего обмена, отмена, отзыв доверия и выбор разрешённых пространств |

При первом запуске показывается список заметок и одна кнопка создания. Настройка сети не блокирует начало работы. Статусы различают «Сохранено на устройстве», «Есть изменения для отправки», «Синхронизировано», «Устройство недоступно» и «Нужен выбор версии». Таймер повтора не выдаётся за успешный обмен. Кнопки имеют доступные подписи, масштабирование текста и достаточные зоны касания; цвет не является единственным индикатором.

## 3. Содержимое и wiki-ссылки

Desktop использует PySide6 и сохраняет `QTextEdit.toHtml()` в `notes.body`; это не Markdown-хранилище. Парсер связей работает с видимым текстом HTML. Мобильный редактор обязан учитывать этот контракт.

- Поддерживаются `[[Название заметки]]` и `[[Название заметки|Алиас]]`. Ввод `[[` открывает предложения из текущего пространства; при одинаковых заголовках показывается дополнительный контекст, произвольная первая запись не выбирается.
- UUID идентифицирует сущность при обмене; текстовая wiki-ссылка сохраняет нынешнюю семантику разрешения по заголовку. Переименование и обновление ссылок должны соответствовать desktop-правилам.
- Исходный HTML и неизвестные поля передаются без потерь. Простое преобразование HTML → Markdown → HTML запрещено как способ сохранения.
- До доказанной совместимости редактора неподдерживаемое форматирование открывается для безопасного просмотра. Редактирование такой заметки требует отдельного подтверждённого пути с сохранением исходной версии; скрытое упрощение недопустимо.
- Скрипты, сетевые загрузки и активное содержимое HTML не выполняются. Отображение очищается отдельно от сохранённого исходного тела; внешние ссылки требуют явного действия.
- `note_links`, поисковые индексы и раскладка графа вычисляются локально из заметок. Целочисленные ID строк графа не являются протоколом синхронизации.

## 4. Слои Flutter/Dart и локальное хранилище

Предлагаемые границы: `View → ViewModel → NotesRepository / SyncRepository → SQLite / PeerTransport`. Репозитории — единственная точка изменения данных; экран получает локальный поток состояния. Это следует подходу [Flutter offline-first](https://docs.flutter.dev/app-architecture/design-patterns/offline-first).

SQLite хранит заметки, пространства, связи, локальные настройки, журнал операций, входящие операции и подтверждения. Одна транзакция сохраняет изменение заметки и исходящую дельту. Отдельный исполнитель БД не блокирует кадры UI. Сеть не читает изменяемые таблицы напрямую из виджетов.

Аддитивная desktop-миграция сохраняет старые целочисленные PK/FK и добавляет глобальную UUIDv4-идентичность. Мобильная схема может иметь собственные локальные ключи, но в протоколе использует UUID. Название пространства не служит идентификатором или разрешением доступа. Совпадающие заголовки заметок не разрешаются случайным выбором цели wiki-ссылки; неоднозначность показывается пользователю. Схема обмена и правила конфликтов определяются [P2P-архитектурой](P2P_SYNC_ARCHITECTURE.md).

Конкретные Dart-пакеты SQLite, редактора, криптографии и discovery выбираются отдельными ADR после проверки сопровождения, лицензии, поддержки целевых ОС и тестов совместимости. Спецификация не закрепляет непроверенные версии. Нативные API подключаются через типизированные интерфейсы и [Flutter platform channels](https://docs.flutter.dev/platform-integration/platform-channels), если подходящего проверенного адаптера нет.

Desktop-переносимость `AppDir/ai/` и `AppDir/stt/` не переносится буквально на мобильные ОС: приложение хранит данные в своём системном контейнере. Экспорт/импорт выполняется через системный выбор файлов, ключи устройства — через защищённое хранилище ОС. Копирование каталога приложения не считается мобильным способом резервного копирования или переноса доверия.

## 5. Сеанс синхронизации

1. Пользователь открывает подключение устройства. Ограниченное по времени обнаружение публикует только временный идентификатор и параметры подключения, без названий заметок и пространств.
2. Android-адаптер использует DNS-SD/NSD; iOS — системный Bonjour-адаптер. [Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd) описывает обнаружение служб, но обнаружение само по себе не подтверждает доверие. Нынешний эксперимент UDP в репозитории не объявляется готовой реализацией mDNS.
3. Пользователи сверяют привязанную к криптографическому рукопожатию идентичность через QR или проверяемую строку на обоих экранах. Доверие и доступ к каждому пространству подтверждаются явно. Подробности E2EE и отзыва — в P2P-архитектуре.
4. Транспорт проверяет доверие, версию протокола и актуальное разрешение на пространство перед каждой входящей/исходящей пачкой. Используются ограниченные размеры, дедлайны и отмена.
5. Входящая операция проверяется по схеме, UUID, области доступа и лимитам; повторный `op_id` (в прототипе пара `actor_id` + `clock`) не применяется второй раз. Применение, запись в inbox и обновление позиции подтверждения атомарны. ACK отправляется только после commit.
6. Неподтверждённые outbox-операции остаются после обрыва и повторяются при следующем сеансе. Неподдерживаемые версии/поля не отбрасываются молча: сеанс останавливается либо данные сохраняются как неприменённые согласно протоколу.

Конкурентное редактирование текста не должно незаметно уничтожать проигравшую версию. Интерфейс показывает обе версии для сравнения и сохраняет историю конфликта. Tombstone препятствует воскресанию удалённой заметки после долгого отключения; очистка tombstone требует отдельного протокола подтверждений. Архив и корзина — состояния заметки, а не удаление сетевой истории.

Отзыв доступа останавливает новые передачи и аннулирует локальное разрешение. Он не обещает удаление уже полученной копии с чужого устройства. Перенос заметки в другое пространство перепроверяет разрешения и не отправляет содержимое через старую область доступа.

## 6. Фоновая работа и разрешения

Первая версия синхронизирует по кнопке и при открытом приложении. Android ограничивает фоновую работу: подходящий механизм выбирается по типу операции; длительная работа не маскируется бесконечным скрытым сервисом. См. [Android background tasks](https://developer.android.com/develop/background-work/background-tasks).

На iOS фоновое выполнение управляется системой: регистрация задачи не гарантирует нужное время запуска. Фоновая синхронизация — дополнительная возможность, а не обещание постоянного LAN-сервера; приложение возобновляет незавершённый обмен при открытии. См. [Apple Background Tasks](https://developer.apple.com/documentation/backgroundtasks) и [выбор фоновой стратегии](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app).

Запрос доступа к локальной сети на iOS объясняется до начала обнаружения; Bonjour-службы и описание использования настраиваются в пакете. Отказ оставляет заметки доступными и показывает способ открыть системные настройки. Проверки выполняются по [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy). Требования Android к разрешениям проверяются для фактических target SDK и версий ОС до выпуска.

Микрофон и уведомления не запрашиваются при первом запуске. Они запрашиваются только при включении соответствующей реализованной функции, с обработкой отказа. LAN может быть недоступна из-за изоляции Wi-Fi, VPN или межсетевого экрана: нужен QR/ручной адрес как путь подключения, но он не обходит запрет локальной сети и не отменяет проверку ключей.

## 7. Приёмка перед заявлением о поддержке мобильных ОС

| Проверка | Критерий |
| --- | --- |
| Два физических устройства | Android–desktop и iOS–desktop: сопряжение, ручной обмен, восстановление после обрыва; отдельно проверяются Android–iOS |
| Совместимость v0.1.5 | Копия реальной БД мигрирует с сохранением PK/FK, HTML, напоминаний и пространств; исходная резервная копия открывается v0.1.5 |
| Две офлайн-правки | Любой порядок и дубли доставки сходятся; обе конфликтующие версии доступны пользователю |
| Удаление, архив, корзина | Нет воскресания из старой реплики; фильтры связей и графа соответствуют desktop-контракту |
| Изоляция | Недоверенное устройство, подмена UUID пространства и отзыв в середине пачки не раскрывают данные; перенос пространства перепроверяется |
| Перезапуск | Принудительное завершение до/после commit и ACK не теряет outbox и не дублирует эффекты |
| Форматирование | Богатый HTML и неизвестные поля проходят round-trip; неподдерживаемое содержимое не перезаписывается упрощённым текстом |
| Разрешения и сеть | Отказ локальной сети, фоновые ограничения, смена Wi-Fi и недоступный peer не блокируют редактор |
| Доступность | Крупный системный шрифт, экранный диктор и экран малого размера сохраняют доступ к сохранению и отмене |

Моки проверяют контракт, но не заменяют физические проверки Bonjour, фонового жизненного цикла, защищённого хранилища и разрешений. До прохождения этой таблицы статус остаётся «архитектура и прототип», без утверждения о готовом мобильном клиенте.
