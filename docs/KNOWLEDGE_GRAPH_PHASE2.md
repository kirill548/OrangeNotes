# v0.1.5: автономный обход и масштабирование

## Многошаговый запрос Companion

В параметрах контекста выберите «Пусть помощник выберет связи» и прикрепите
начальные заметки. По умолчанию автономный обход выключен.

1. Приложение проверяет начальные заметки, их пространство, состояние и ревизии.
2. Ollama получает только схемы `get_linked_notes` и `get_backlinks`, вопрос
   и изолированные недоверенные фрагменты. Модель выбирает один вызов или завершает поиск.
3. Строгий валидатор проверяет вызов. Разрешены только начальные ID и ID,
   полученные ранее через разрешённые связи; модель не задаёт пространство или фильтры.
4. Ответ инструмента добавляется в диалог. Следующий вызов повторяет проверки.
5. Из актуальных источников собирается окончательный RAG-запрос. Ответ проходит
   существующие проверки цитат, ревизий и `StreamSegmentValidator`.

Лимиты: три вызова инструментов, глубина два, восемь дополнительных заметок,
бюджет входных токенов и единый дедлайн модельных запросов 30 секунд.
Повтор инструмента для той же заметки останавливает цикл. Невалидные вызовы,
чужие ID, смена ревизии, отмена и ошибки транспорта обрабатываются безопасно.
В ответе есть `graph_tool_audit`: число шагов, максимальная глубина и причина остановки.
Промежуточный текст/мышление модели не используются как доказательства.

## Инкрементальный индекс

`note_links_dirty(note_id)` объединяет изменения одного источника.
`note_links_title_dirty(workspace_id,title)` сохраняет старые и новые названия.
`note_links_titles` индексирует Unicode-нормализованные заголовки по пространству.
В `note_links` добавлен индексируемый `target_key`.

После изменения названия, переноса, создания или удаления обновляется индекс
заголовков и очередь зависимых источников. Правка тела без изменения заголовка
пересобирает только этот источник. Транзакция обрабатывает до 128 тел заметок.
Существующая база мигрируется с начальной переиндексацией; старые резервные копии
поддерживаются строгой проверкой точных определений служебных триггеров.

## Физическая раскладка

Алгоритм использует притяжение по рёбрам, отталкивание через сетку до 144 ячеек,
центральную силу и охлаждение. Это приближённый force-directed алгоритм,
а не полный квадратичный Fruchterman–Reingold. Одна итерация имеет стоимость
O(144N + E); число итераций ограничено 100, по умолчанию 45.

Расчёт выполняет один объединяющий обновления QThread. Устаревшие результаты
отбрасываются, закрытие отменяет расчёт. QTimer с интервалом 16 мс плавно
приближает узлы к рассчитанным позициям; это целевой интервал, не измеренный FPS.
Фильтрация сохраняет позиции оставшихся узлов и масштаб. Смена активной заметки
перекрашивает узел без повторного расчёта. Скрытие останавливает анимацию.

## Проверки и границы утверждений

Первый полный локальный прогон: 1141 PASS, 12 SKIP, 0 FAIL; 1341 успешный subtest.
После визуальной проверки добавлен тест начального кадрирования малого графа;
все 11 UI-тестов графа проходят. Всего добавлены 24 теста, включая многошаговый нативный Tool Calling с тестовым транспортом,
запрет чужих ID, лимиты, архивный мост, смену ревизии, отмену, дедлайн,
миграцию очереди, набор из 550 заметок и жизненный цикл анимации.

Живая Qwen3:4b в этой сессии не квалифицирована: локальный Ollama недоступен.
Тесты с контролируемыми ответами подтверждают реализацию и ограничения цикла,
но не точность выбора инструментов реальной моделью. Скачивание моделей не выполнялось.
Метрики синтетической раскладки не гарантируют читаемость плотного графа или 60 FPS.
Непосредственное сохранение заметок через графовые инструменты не разрешено.
