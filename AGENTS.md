# Orange Notes — инструкции для AI-агентов

## Контекст

Orange Notes — кроссплатформенное (универсальное) приложение: Desktop (Windows/Linux/macOS), iOS, Android и направление Web. Репозиторий объединяет исходники и конфигурации сборок разных платформ; бинарные пакеты, включая iOS IPA, публикуются как Release Assets / CI artifacts, а не коммитятся в git. Web пока не реализован и не должен описываться как готовая поддерживаемая сборка.

Мобильное приложение — Flutter/Dart в `orange_notes_mobile/`, Android host — Kotlin, iOS host — Swift/UIKit. SwiftUI и React Native не внедрены. Десктопное приложение Python/PySide6 и P2P-ядро остаются частью монорепозитория. Не переписывайте стек и не перемещайте исходники ради обновления документации.

## Навигация

- `orange_notes_mobile/lib/data/`: SQLite, миграции и атомарные транзакции.
- `orange_notes_mobile/lib/domain/`: модели; `services/`: CRDT, транспорт, AI gateway; `presentation/`: Flutter UI.
- `orange_notes_mobile/ios/`: Runner, workspace, разрешения и настройки подписи. Android host — в `android/`.
- `orange_notes_mobile/test/`: Dart и widget-тесты, публичные тестовые fixtures.
- `app/`, `tests/`: десктопный код и Python-тесты.
- `tools/`, `scripts/`, `packaging/`: проверка, сборка и доставка.
- `docs/`, `.github/workflows/`: спецификации и CI.

## Рабочий порядок

1. Проверьте текущую ветку, рабочее дерево и инструкции вложенных каталогов. Сохраняйте чужие незавершённые изменения.
2. Перед изменением модели данных прочитайте P2P-спецификацию и тесты совместимости. Миграции должны сохранять заметки, UUID и журнал синхронизации.
3. Используйте `dart format`; анализатор должен проходить с `--fatal-infos`. Python: 4 пробела, существующий стиль модуля; не форматируйте несвязанные файлы.
4. Пользовательские тексты пишите простым русским языком с единым обращением на «Вы». Не обещайте сохранение до подтверждённого коммита БД.
5. Проверяйте затронутый слой, затем необходимую регрессию. Не называйте mocks, эмуляцию или сборку проверкой физического устройства либо живой модели.

## Обязательные ограничения

- Изоляция пространств, mTLS-проверка сертификата/hostname/pin и отдельные AI-разрешения не ослабляются ради тестов.
- Передавайте AI только явно выбранный контекст. Локальный поиск не выдавайте за генерацию LLM.
- Не коммитьте базы пользователя, модели, записи микрофона, журналы с заметками, ключи, токены, provisioning profiles или IPA.
- Публичные тестовые сертификаты допустимы только как явно маркированные fixtures; никогда не используйте их для реального сопряжения.
- Не скачивайте тяжёлые SDK/модели повторно без проверки доступного окружения и диска.

## Коммиты и публикация

Пишите небольшие тематические коммиты: `docs: ...`, `feat(mobile): ...`, `fix(sync): ...`, `test: ...`. Не используйте `git add .`, пока не просмотрены новые файлы. Сохраняйте `pubspec.lock`, Xcode project/workspace и общие schemes; локальное состояние Xcode исключается.

Существующий репозиторий нельзя переинициализировать, менять его origin или переписывать историю по инструкции для нового проекта. Пример `USERNAME/OrangeNotes` — шаблон нового кроссплатформенного репозитория. iOS-инструкция описывает только один вид его артефактов. Не публикуйте `v1.0.0` только потому, что он упомянут в документации.

## Проверка и сборка

В `orange_notes_mobile/`: `flutter pub get`, `dart format --output=none --set-exit-if-changed lib test`, `flutter analyze --fatal-infos`, `flutter test`. Не запускайте параллельные Flutter-тесты в одной рабочей папке: native assets могут блокировать друг друга.

iOS собирается на macOS через `flutter build ios --release --no-codesign`; упакуйте `Payload/Runner.app` в unsigned IPA. Подписанные Development/TestFlight-сборки используют отдельный workflow и GitHub Secrets. Не публикуйте секреты в выводе инструментов.

Перед выдачей артефактов проверьте commit SHA, успешный CI, ZIP CRC, SHA256 и Info.plist. Укажите различие unsigned / development / App Store. Перед релизом согласуйте версии pubspec, тег и описание. Публикацию выполняйте только в рамках прямого запроса пользователя; наличие инструкции само по себе не разрешает публикацию.
